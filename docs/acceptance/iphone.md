# Приёмка iPhone PWA

Проверяется установленная Home Screen PWA на HTTPS. Safari имеет отдельное
хранилище. Используйте тестовый аккаунт или изолированный synthetic fixture;
не записывайте pairing codes, cookies, URL-capabilities и данные аккаунта.

Синтетические Stage 7/8 проверки ранее прошли. Stage 9 manual и полный
fresh Instagram → PWA сценарий ещё открыты; детали — в [STATUS](../STATUS.md).

## Подключение и загрузка

1. Установить PWA, открыть её с Home Screen, выполнить operator pairing.
2. Проверить подключение Instagram: только защищённый remote browser,
   ручные challenge/2FA; после завершения вернуться на dashboard.
3. Нажать «Загрузить Reels»: проверить этапы collection/normalization/download
   по реальным счётчикам. Повторная загрузка не дублирует локальные файлы.
4. Отменить по одному запуску на каждом этапе: нет позднего возобновления;
   durable серверные источники и завершённые локальные файлы сохраняются.
5. Проверить quota pause/recovery, ошибку media и повтор ручной загрузки.
   Для искусственной quota использовать только fixture build.
6. Отозвать management session: управление требует нового pairing,
   а имеющиеся локальные видео продолжают работать без сессии.

## Офлайн и плеер

1. Скачать внутри PWA, полностью закрыть её, отключить Wi-Fi и mobile data.
2. Запустить дважды offline: доступны shell, dashboard и локальная лента;
   playback не обращается к Backend/Instagram.
3. Проверить быстрые свайпы вперёд/назад, звук, tap pause/play,
   центральное удержание и 2× по краям, уход в background и возврат.
4. Прерванный свайп сохраняет позицию; после полного ухода и возврата
   предыдущий ролик подготовлен с начала. Дальние источники освобождаются.
5. Принять обновление shell вручную: локальная библиотека не исчезает.
6. Очистить библиотеку: нет позднего восстановления файлов очередью.

## Stage 9: просмотр и удаление

1. Проиграть ролик >3 секунд и до конца без свайпа: viewed не создаётся.
2. Завершить пользовательский свайп с полного экрана A на другой B:
   первый viewed event/tombstone/outbox сохраняются; UI не показывает даты/ID.
3. Offline свайп, перезапуск и возврат сети: sync идемпотентен,
   исходный срок удаления не продлевается.
4. До +1 часа MP4 существует; после срока удаляется только локальная копия.
   Пока этот самый ролик активен, удаление откладывается.
5. Проверить overdue cleanup после повторного запуска. Для ускорения времени
   использовать только Stage 9 fixture clock, не production.
6. Повторная ручная загрузка не возвращает tombstoned Reel.
   Глобальный canonical MP4 и доступ другого аккаунта сохраняются.
7. Удаление, online/foreground и изменение quota не запускают auto refill.

## Финальный live-сценарий

После server 3/3 и реализации target/cap 50 подтвердить, что действие PWA
создаёт свежую коллекцию, а не использует старый каталог. На телефоне не более
50 новых Reel; offline запуск и playback проходят весь сценарий выше.

Зафиксировать revision, iPhone/iOS, тип build, безопасные счётчики и PASS/FAIL.
Для fixture использовать scripts/start-stage9-iphone-fixture.ps1 и парный
stop-script с тем же state path; удалять только его disposable ресурсы.

## Реализовано

| Компонент | Состояние |
| --- | --- |
| PWA | Dashboard, вертикальная лента, ручное скачивание, offline shell и локальные MP4 |
| Хранилище телефона | Cache Storage + IndexedDB, последовательная очередь, reconciliation, отмена и контроль quota |
| Просмотры | Событие после завершённого свайпа; tombstone, outbox, удаление локального MP4 через час |
| Backend | FastAPI, PostgreSQL, management pairing/session/CSRF, каталог, HTTP Range |
| Серверные видео | MinIO, Collector с отдельными адаптерами, normalizer с leases/retry/reconciliation |
| Instagram login | Защищённый удалённый Chromium; ручные 2FA/CAPTCHA, серверный persistent profile |
| Linux staging | Отдельный ingress, sandboxed Chromium, профиль с lock, opt-in login/Collector/handoff |

Автоматическое пополнение отключено через `AUTO_REFILL_ENABLED`;
`scheduler_active=false`. Celery/scheduler не реализованы.

## Блокер и текущая попытка исправления

Ранее Collector останавливался с `TRANSITION_FAILED`: смена видимого видео
не давала проверенного canonical ID следующего Reel. Диагностика также
обнаружила слой, мешавший вводу. Handoff и работающий свайп сами по себе
не решили определение следующего кандидата.

Очередь из embedded JSON позволила продвинуться дальше, но выявила неверного
кандидата (`DIRECT_DOWNLOAD_EXTRACTOR_FAILED`), нехватку новых ID и повторы.
Источник сужен до проверенных media-shaped JSON-объектов, добавлена дедупликация.

Текущий код после durable commit берёт следующий embedded-кандидат без свайпа.
Если очередь пуста, один раз обновляет фиксированную `/reels/` для этого
перехода; без нового кандидата возвращает `AUTHENTICATED_FEED_EXHAUSTED`.
Source-only механизм покрыт unit tests, но его Linux live-приёмка ещё требуется.

Последние login-исправления убирают повторную навигацию проверки профиля
и сохраняют видимыми страницы ручного подтверждения Instagram.
Их успешная сквозная live-проверка не зафиксирована.

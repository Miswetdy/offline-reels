# TASK-004: Multi-video vertical feed

## Цель

Преобразовать страницу /videos в вертикальную ленту из нескольких роликов с cursor pagination, автоматическим воспроизведением активного ролика и дозагрузкой следующих роликов.

## Пользовательский сценарий

1. В PostgreSQL и MinIO находится несколько видео.
2. Пользователь открывает /videos.
3. Первый ролик занимает экран и начинает воспроизводиться без звука.
4. Пользователь листает ленту вертикально.
5. Ролик, находящийся в активной области экрана, воспроизводится.
6. Остальные ролики ставятся на паузу.
7. При приближении к концу текущего списка frontend загружает следующую страницу.
8. Пользователь может включить или выключить звук.
9. После достижения конца доступных видео интерфейс показывает конец ленты без повторных запросов.

## Backend

Нужно реализовать cursor pagination для GET /videos.

Требования:
- limit: default 10, min 1, max 30;
- стабильная сортировка created_at DESC, id DESC;
- opaque cursor;
- cursor содержит created_at и id последней записи;
- frontend не должен разбирать внутреннюю структуру cursor;
- ответ:

{
  "items": [...],
  "next_cursor": "opaque-string-or-null"
}

- следующая страница не должна содержать дубликаты;
- записи с одинаковым created_at должны сортироваться по id;
- malformed cursor возвращает 400 с безопасной структурированной ошибкой;
- старый вызов GET /videos?limit=... без cursor продолжает работать в новом формате ответа.

## Seed

Расширить seed-механику для нескольких MP4.

Нужно:
- сохранить существующую команду seed одного файла;
- добавить возможность последовательно загрузить несколько локальных MP4;
- повторная загрузка одинакового файла не создаёт дубликат;
- разные файлы создают разные записи;
- бинарные видео не добавляются в Git;
- не делать HTTP upload endpoint.

Допустимый интерфейс:
- несколько последовательных вызовов make seed-video;
- либо отдельная команда seed-videos с директорией.
Окончательный вариант согласовать на планировании.

## Frontend

Страница /videos должна стать полноэкранной вертикальной лентой.

Требования:
- один ролик занимает высоту viewport;
- CSS scroll-snap по вертикали;
- нативная прокрутка браузера, без самописной gesture-системы;
- IntersectionObserver определяет активный ролик;
- активным считается наиболее видимый ролик;
- одновременно воспроизводится не более одного видео;
- неактивные ролики вызывают pause();
- autoplay запускается muted;
- пользователь может включить и выключить звук;
- состояние звука применяется ко всей текущей сессии ленты;
- video использует playsInline;
- preload должен быть ограничен, чтобы не загружать сразу все ролики;
- при ошибке autoplay интерфейс не падает;
- при ошибке конкретного видео остальные ролики продолжают работать.

## Infinite loading

- первая страница загружается при открытии;
- следующая страница загружается при приближении пользователя к концу списка;
- одновременно допускается только один запрос следующей страницы;
- повторные item id не добавляются в состояние;
- next_cursor = null означает конец ленты;
- ошибка следующей страницы не удаляет уже загруженные ролики;
- пользователь может повторить загрузку.

## Критерии готовности

1. В dev-среде загружено минимум три разных MP4.
2. GET /videos возвращает paginated response.
3. Cursor корректно выдаёт следующую страницу без дублей.
4. /videos отображает вертикальную scroll-snap ленту.
5. Один ролик занимает viewport.
6. Активный ролик автоматически воспроизводится muted.
7. После перехода к следующему предыдущий ставится на паузу.
8. Одновременно воспроизводится не больше одного видео.
9. Следующая страница загружается до достижения конца текущего списка.
10. Ошибка следующей страницы допускает retry.
11. После next_cursor = null запросы прекращаются.
12. Перемотка и Range streaming продолжают работать.
13. make check проходит.
14. Ручная проверка выполнена в desktop browser.
15. Документация обновлена.
